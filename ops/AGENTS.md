# ops/: host-side operations

Everything that runs on the WSL host (user `owner`) rather than in a container: the Mission Control runner, deploys,
backups, keys, scheduled jobs and setup. Started by `make` targets, systemd user units (`systemd/`) or the runner.
Secrets arrive as environment variables from `sops exec-env`. Scripts never decrypt files themselves.

## Rules

- **The runner is the only executor.** Requests from the app and from Hermes' tools arrive in the inbox;
  `missions.py` `handle()` validates them (allow-listed actions, slugs, schedules, sizes) before anything runs. New
  actions: validation + an event in `events.jsonl` + a unit test in `tests/test_runner.py` or `tests/test_builds.py`.
- **Long-running code is defensive.** Threads of the runner catch and log their errors and keep going. One failing
  mission must never stop the others.
- **Subscription pauses are normal.** Model calls can fail with the ChatGPT usage limit. Detect it (`paused()`), wait
  and retry, and never mark the job as failed.
- **Files shared with containers** are written with umask 0 and atomically (write a temp file, then rename).
- **No silent cuts** (root AGENTS.md, Truncation):
  - A request's text over its limit is refused with `textcap.limit()`; the app shows the message.
  - Text the owner will read is stored whole, or cut with `textcap.cut()` or `tail()` at `STORE` or more.
  - Events, Telegram lines, errors and log lines carry the whole message (`{e}`, not `str(e)[:200]`).
  - Prompts may be bounded: tag them `# cap: prompt`.
  - `ops/truncation.py check` enforces the tags.
- Python: stdlib first, `sh()` for subprocesses (it logs failures), no new dependencies on the host beyond
  `pyyaml` and `markdown`. Shell: `set -euo pipefail`, `cd "$(dirname "$0")/.."` when paths are repo-relative,
  and every script passes `shellcheck -S error`.
- A script that the owner runs gets a `make` target with `## help`, and that target is mentioned in the guide
  (`images/mission-control/guide/15-operations.md`; `tests/test_guide.py` enforces it).
- `deploy.py` and `builds.py` are on the builder's sensitive list: changes to them are flagged in review.

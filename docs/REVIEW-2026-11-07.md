**State reviewed:** `main` at `8b561a2` (7 Nov 2026 16:44), deployed at 17:02 the same day. Baseline `make check`:
ALL CHECKS PASSED, 1,196 tests passed, 1 skipped, 10 minutes. Everything green, and still the review found two defects

the gaps are in what nothing checks.

## Verdict

The stack is far more disciplined than most personal projects (requirements traced to tests, truncation and limit rules
enforced, encrypted backups with a drill, sealed connectors). It is **not yet production grade**, for three reasons:

1. **The sandbox boundary does not hold.** The builder sandbox can make the host runner (which holds every secret and
   the Docker socket) run code, and can make unreviewed code reach `main` (SEC-R1, RUN-R2, RUN-R7). The builder and
   OpenCode also sit on a flat network with services that hold the vault and mail and trust a header anyone there can
   send (SEC-R2, APP-R8). The branch closes the paths that could be closed safely; the network design is the owner's call.
2. **Recovery is unproven where it matters.** A restore on a new PC has aborted halfway every time it ran (OPS-R1), the
   Bitbucket mirror has been silently stuck since 25 October (OPS-R3), and the nightly backup is skipped (counted "ok")
   whenever an app it does not even need is down (OPS-R4). All three are fixed in the branch; the restore fix still needs
   one rehearsal on the owner's side.
3. **The newest code (memory stack, 7 Nov) leaked private memory to the web-reading scout** through a caller-supplied
   name (MEM-R1/R2) and marked nothing as untrusted in practice (MEM-R7). Fixed in the branch for the paths found;
   the identity design (MEM-R3) and what counts as public (MEM-R4, DOC-R3) are the owner's decisions.

### Security boundaries

- **S1 · SEC-R1 rest · critical.** The runner should never run git in a folder the sandbox can write. *Recommendation:* the
  runner keeps its own clones outside `/srv/ai/workbench` and takes the builder's work in as data (a bundle the builder
  writes, fetched with hooks off); until then SEC-21's seal covers the deploy path only.
- **S2 · SEC-R2, APP-R8 · critical.** The builder and OpenCode share the flat `backend` network with Phoenix (prompt
  traces, no login), qmd (vault and mail, MCP without auth), OpenCode itself, Open WebUI and the Hermes dashboard gate, and
  Mission Control's ports 8090-8098 trust a `Tailscale-User-Login` header any container there can send.
  `docs/SECURITY.md:17` says the builder's networks are "LiteLLM + npm/PyPI proxy". *Recommendation:* an internal network
  shared only with LiteLLM for the builder (OpenCode: LiteLLM and graphify); gates and Mission Control accept the header
  only from the published-port network's gateway; a bearer token per MCP server that LiteLLM sends.
- **S3 · SEC-R3 · high.** The CI runner sits on `edge` with Hermes and LiteLLM and runs every pushed builder branch before
  review, with the runner registration readable. *Recommendation:* its own network; CI on `builder/*` only after review or
  with the job isolated from the registration.
- **S4 · DOC-R3, MEM-R4 · high.** `vk-scout` holds `memorypublic` (the vault wiki, non-private mission wikis, playbooks,
  skills) against SEC-03 ("no access to the vault, memory, mail"); 10 of 26 vault-wiki source pages come from mail. Either
  remove the grant, or reword SEC-03 with an accepted risk in SECURITY.md and exclude mail-derived pages and the
  assistant's and missions' playbooks from the public class. Also SEC-08 for `vk-builder`/`vk-code`.
- **S5 · MEM-R3 · high.** Inside a class, the caller's own `agent` argument still decides own-journal access, the memory
  agent's override and a mission's private wiki, and a public-class note can be filed into a private role's playbook
  unlabelled. *Recommendation:* identity from the key (LiteLLM passes it), public-class notes marked untrusted and kept to
  public roles.
- **S6 · SWM-R1, SWM-R2, SEC-R8 · high.** The Ledger cannot label a Board message private through its MCP door, so SWM-67
  never runs in production; the duplicate guard, `swarm_context` and watched-change reasons hand private titles and text to
  way-out agents (reproduced). *Recommendation:* label by the sender's card; filter those three read paths by `sees()`.
- **S7 · APP-R2 · high.** Model-written Markdown can load remote images (data out in the URL) and restyle the page; there is
  no Content-Security-Policy. *Recommendation:* a CSP (`img-src 'self' data: blob:`, `connect-src 'self'`) and DOMPurify
  without `style`/forms.
- **S8 · APP-R4 · high.** Chat attachments (`.html`, `.js`) are served inline from the app's own origin; a shared or
  mailed HTML file runs with the whole API. *Recommendation:* `Content-Disposition: attachment`, `nosniff`, `CSP: sandbox`
  on `/api/chat/files/*` (a small change; left for sign-off only because it changes how files open on the phone).
- **S9 · CNX-R4, SEC-R13 · medium.** `from_ai_phone` compares only the phone's tailnet IPv4; over its tailnet IPv6 every
  PHN-07 guard is skipped. *Recommendation:* add the phone's IPv6 (or its node identity) and a test; restrict the phone in

- **S10 · SEC-R6.** The builder's proxy allows `proxy.golang.org` and `api.anthropic.com`, both general egress; SECURITY.md

- **S11 · IMG-R1 rest.** The desk is the only web reader without the egress firewall the other web readers have.
- **S12 · SEC-R7.** Semgrep's port rule misses block-style lists (the NAS Forgejo publishes 3000 and 2222 on all

### The pipeline and the runner

- **P1 · RUN-R7 · medium.** Killing `docker exec` does not stop the agent inside; a resumed build can share a tree with
  the old one, and `push -f origin <branch>` pushes whatever HEAD is then. BLD-28 now stops such a head at the merge;
  *recommendation:* kill by build id in the container and push the reviewed `head`.
- **P2 · RUN-R6, RUN-R12, RUN-R13, RUN-R11, RUN-R10.** The runner restart after a deploy is unconditional and kills the next
  deploy; the builder's deploy does not take land.sh's lock; land.sh has no rollback (AGENTS.md says every deploy has one);

  unit the change added. These are deploy-behaviour changes: one design pass over deploy/land/restart.
- **P3 · RUN-R3 · high.** "Usage limit" is detected in free text (the build's own summary), so finished builds re-ran up to
  12 times (#44, #50, #7 live) and Claude tasks can loop. *Recommendation:* only on a failed process and the gateway's error
  signature (could be a SAFE-FIX; not done for lack of a way to test it against real runs).
- **P4 · RUN-R14 · medium.** The builder's checks gate is "PASSED" anywhere in the last 40 lines, exit code ignored.
- **P5 · SWM-R5 · high.** The experiment gate rewards an agent that goes silent: change #380 ("prefer sending zero ideas")

## Do the tests protect production? (test-quality review)

Measured on throwaway copies with `--network none`: line and branch coverage of `ops/` and `images/` is 70 %, but
`ops/deploy.py` is at 30 % and `ops/restore_check.py` at 34 %. Of **73 single-point mutations** in the 11 most critical
modules, **25 survived** (the code broke and no test failed): 6 of 9 in `deploy.py` (a failed health check, a failed step
or a removed smoke test still says DEPLOY OK, so automatic rollback could silently stop working), 5 of 5 in `land.sh`
(its tests only grep its text), 4 of 7 in the runner's request validation, 4 of 11 in the phone's purchase path (three
now killed by QA-R5), 2 of 2 in `restore_check.py`. The suite passes without network and in any time zone; it has one
flaky test (QA-R17), sleeps for real in every journal write (6 of 6.7 s of a shopping test, QA-R16; the suite takes 11-15
minutes, `tests/AGENTS.md` says under one), and **writes into this machine's production folders** when run on the host
(`/srv/ai/missions/public/swarm.json`, the runtime spool, memory trial state; QA-R18).

What it recommends (SAFE-FIX unless marked): unit tests of `deploy.main()` (QA-R1) and of the builder's worker, revert and
review paths (QA-R7); one strict pass rule for builds, Conductor and land.sh (exit code and the last line, QA-R2 = RUN-R14);
redirect every `/srv` and home path in the test fixture and fail on a write outside tmp (QA-R18); tests of the AI phone's
refusals and of the runner's validation (QA-R6, R8, R9); a compose-policy test in place of the semgrep port rule (QA-R11);
the truncation and limits checkers' blind spots, with four real silent cuts and five untagged limits found through them
(QA-R12, R13; e.g. a paused run stops after 8 h, `MAX_WAITS`, invisible in `docs/LIMITS.md`); checks that pass when they
could not run (QA-R14: the frozen benchmark check passes when both files are gone; `app_lint` lints nothing if
`index.html` changes shape; the journeys test is always skipped because the CI image has no `make`). Sign-off: land.sh's
missing rollback and compose check (QA-R4 = RUN-R13), 152 tests that only read source text (QA-R20), the builder may

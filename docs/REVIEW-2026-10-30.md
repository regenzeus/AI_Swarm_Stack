# Wide review of the AI stack, 30 October 2026

Asked for in chat on 2026-10-30: *a wide review, with a method first, several sweeps with different focus, then fix the
findings, aiming for a polished, production-grade stack with requirements in sync, excellent documentation and
excellent UX.* This review covers the whole repository at `61e3bf1` (315 commits) and the running stack. It builds
on the review of 27 October (`docs/REVIEW-2026-10-27.md`) and the UX review earlier today (`docs/UX-REVIEW-2026-10-30.md`).

## Method

### Rules

- **Evidence or it is not a finding.** Each finding names a file and line, a command and its output, or a screen and
  what it showed. "Might be a problem" goes under *Watch*, not under findings.
- **Look at the running stack, not only the code.** What runs, fails, grows or is never read counts as much as what
  the code says.
- **Change nothing while sweeping.** Fixes come after all sweeps, so they are ranked against each other, not done
  in the order they were found.
- **Every finding goes into `requirements/findings.yaml`** with severity, kind, evidence and the requirement it
  affects, so the requirements and the review stay in sync.
- **Safe probes only.** No real mission is run to test something, because it would deliver to the owner. The
  click-through records writes instead of sending them. Nothing is deleted.

### Sweeps

| # | Focus | Probes |
|---|---|---|
| 1 | **Live operations and reliability** | health board items; failed and overdue systemd units; container restarts and their logs (7 days); crew jobs' last results; backups and the restore drill; disk, RAM and data growth; usage-limit waits |
| 2 | **Requirements in sync** | `ops/req.py check`; every `partial`, `violated`, `proposed` and open finding re-checked against the code; code with no requirement (routes, crew jobs, ops scripts, app screens, prompts); `unmapped-tests.txt`; statements that no longer match what the code does |
| 3 | **Documentation** | README, NEW-MACHINE, UPGRADE, every AGENTS.md and guide page: commands and paths exist, counts and names are current, each guide page's *try* blocks open a real screen, no leftovers of removed features; the 27 October review's open items |
| 4 | **UX** | the click-through (`ops/ui_crawl.js`) on every kind of screen; a visual pass of each top-level screen on a phone and a desktop; wording (internal names, jargon, mixed languages); empty, loading and error states; tap targets and labels |
| 5 | **Security and code quality** | each HTTP route's auth; secrets in the repository and in logs; container privileges and exposed ports; swallowed errors (`except Exception: pass`); dead code; oversized functions; duplication; TODO and FIXME |

### Rating

- **Severity:** *high* means the owner loses data, money, privacy or a result, or is misled. *Medium* means a feature
  is broken or hard to use, or documentation or requirements contradict the code. *Low* means polish.
- **Fix order:** high first, then whatever gives the most for each change. Each batch lands through `ops/land.sh` with
  its tests and requirements, and is checked live where it can be seen.

### What now keeps it in order

These checks are permanent and run in every landing, so the same kind of drift cannot come back unnoticed:

- **Every source file is traced** by a requirement, or listed with its reason in `requirements/untraced-files.txt`,
  and the list only shrinks (QA-18).
- **The API reference is drawn from the code**, and a route without a docstring fails the tests (QA-19).
- **Everything a document names exists**: every path, `make` target, app screen and relative link (QA-20).
- **Silent broad catches can only become fewer** (67 today, QA-17).
- **The tools that take no arguments are rescanned from the code**, so the health board's empty-arguments rule
  cannot fall behind (OBS-07).
- **The health board now also watches the machine**: a restore drill older than 8 days, full swap, and containers
  that run another build than their tag or an image the lock file lacks (PLT-15, PLT-20, CST-14).

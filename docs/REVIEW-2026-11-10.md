## Verdict

The update is ambitious and mostly careful: every fix of 7 Nov in the areas it did not touch still holds, about forty of
the 7 Nov backlog items were done, the new code is traced to requirements, and the scheduling move left no job started
twice or by nobody. But it opened new paths around the boundaries the 7 Nov review closed, and it is not production
grade yet:

1. **n8n is owner-equivalent, and so is anything on the app's networks.** The app trusts the identity header from any
   container that shares a network with it; n8n now does (`stepnet`), and n8n is a program that sends HTTP requests by
   design. A workflow (or a pack's, or anything that can reach n8n's unauthenticated webhooks: the builder sandbox on the
   flat `backend`, any tailnet device on :8450) can approve deploys, grant Gmail, open the phone's free mode, and call the
   house and memory tools without a key. This is 7 Nov's S2, widened. The fix is a design change (below, O1-O3).
2. **New code re-opened two closed holes.** `ops/domain/forgework.py` ran plain git in the builder's workbench, so a hook
   the sandbox planted ran on the host with every secret (SEC-21's hole, again), and its pushes skipped the never-in-git
   guard. Fixed here.
3. **Recovery is broken again for n8n.** A restore now aborts with "RESTORE INCOMPLETE" (n8n's database collides with the
   fresh one), the runner's own Python is made by nothing on a new PC (so nothing runs at all), and the drill never looks
   at n8n. Fixed here; the rehearsal still needs to run.
4. **WSL ran out of memory under load during this review** (7.4 of 8.4 GB, 6.3 GB in swap, a 3 GB code-graph merge),
   and restarted; the backup of 10 Nov was lost the same way at 03:36. A limit is the owner's decision (O9).

## Do the tests protect production? (test-quality review)

123 single-point mutations of the most critical new code and of the 7 Nov fixes ran on a throwaway copy (a WSL
restart at 18:44 cut the run short; no coverage numbers). **37 of 122 survived** (the code broke and no test failed):
the run register's "exactly once" (7 of 14: a wait that was answered stays, so the next comment goes to a dead run; an
answer can be replayed), the egress rule (**an allow-everything rule passed every test**; the only real test is always
skipped), the never-in-git guard in `builds.git` (protected only by a source-text test) and termguard (it fails open
when the remote moved: reproduced), the localworker (its request-id and artifact-size checks), the step service's body
and id checks, the n8n node (a syntax error; fixed above). Killed: the statefile, SEC-20, PHN-07, mail, the BLD-28 head
check and approval, the checks-passed rule, deploy's health, smoke and exit code.
Open from 7 Nov: checks that pass when they could not run (QA-R14: `app_lint` on 0 scripts, a test that returns as
root, skips counted as passes), real sleeps in journal commits, flaky waits (four "busy PC" widenings since 7 Nov),
tests that write into production folders (partly fixed), 152+ tests that only read source text, CI's unhashed packages.
New: the landing checks run on Python 3.14 as root while CI and production run 3.12 (QA2-R8); the Windows worker that
runs commands on a customer's machine has no automated test (QA2-R7); module state shared between parallel tests
(QA2-R9); the runner's state folders are 777 with `shadow.json` in them (QA2-R10, sign-off).

## Open, waiting for the owner (most severe first)

**The trust boundary around n8n and the app**
- **O1 · APP2-R1, SEC2-R1, N8N2-R2, DOM2-R16 · high.** The app's ports (8090 owner API; 8091-8098 MCP: missions, house,
  files, memory with the all class) answer on every network the app joins, and the identity header is not bound to the
  published-port path (local gate: `Host: mission-control` is the owner). *Recommendation:* accept the identity only from
  the published-port path (the source address of the port-publishing network's gateway, to be confirmed live, since a
  wrong value locks the owner out); bind the MCP ports to the networks LiteLLM uses, with a bearer token each; move the
  step service into a container of its own that alone shares `stepnet` with n8n.
- **O2 · N8N2-R1 · high.** The step service (:8099) has no token. *Recommendation:* a sops token the node sends.
- **O3 · SEC2-R2, N8N2-R3 · high.** All 31 workflows' webhooks are unauthenticated, n8n is on the flat `backend` with the
  builder sandbox, and :8450 serves n8n's whole root on the tailnet. *Recommendation:* header auth on every webhook with a
  secret the runner holds; n8n off `backend` (a network of its own with Postgres); :8450 for `/webhook-waiting` only.
- **O4 · SEC2-R5, N8N2-R14.** n8n runs without `cap_drop`, read-only root or `no-new-privileges`; at home the Code, SSH
  and Git nodes and its public API are on. Postgres' superuser (LiteLLM's role) owns n8n's database.
- **O5 · SEC2-R3, DOM2-R6 rest.** The step service lets a workflow run any agent (main, which holds phone, mail and
  house) on tracker text; a tracker comment is "yours" when it ends with the write mark, which anyone can type.
- **O6 · DOM2-R4, R5, R11, R12, R13, R15, OPS2-R8.** The work deployment's boundaries: `wsl` place jobs run in the
  runner's process with every decrypted secret; the wsl-host worker's code is writable by the stack's user; the egress
  rule is lost on every WSL restart and nothing re-applies or probes it, covers the stack's uid only and leaves DNS open;
  the builder's proxy allows api.anthropic.com but not the company gateway (`gateway_only` cannot work); no web-tool ban
  for the builder's Claude under customer data; pushes carry content under customer data.
- **O7 · DOM2-R3.** A tracker item's change is pushed and opened as a draft PR with no checks at all (the CHG-05 `onto`
  shortcut skips the judge); the deployment's own checks never run on the work path.
- **O8 · DOM2-R7, R8, R9, REST2-R7.** Roles (GEN-27) fail open: the deployment's roles file is never read, "owner" means
